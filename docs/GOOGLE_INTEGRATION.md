# Google連携（カレンダー・Gmail・Drive/Docs/Sheets・タスク・連絡先）

**手順の本体は、アプリ内の日本語ページ `/google-setup/` にあります**（画面付きの案内・リンク・状態表示つき）。このファイルは、仕組みと確認状況の記録です。

## できること
| サービス | 読み取り（すぐ実行） | 書き込み（毎回、画面で「承認」） |
|---|---|---|
| カレンダー | 予定の一覧、空き時間 | 予定の追加・変更・削除 |
| Gmail | 検索、本文を読む | 下書き作成、**送信**、**ゴミ箱**へ移動 |
| Drive／Docs／Sheets | 検索、テキスト・シートの読み取り | ドキュメント作成・追記、セルの更新・追加、**ゴミ箱**へ移動、特定の1人への**共有** |
| タスク | 一覧 | 追加・完了・削除 |
| 連絡先 | 検索 | （読み取りのみ） |
| 補助 | 現在の日付・時刻（日本時間） | — |

意図的な制限：メール・ファイルの削除は**ゴミ箱に移すだけ**（約30日は戻せる）。完全削除はしない。共有は**指定した1人のGoogleアカウントだけ**（リンク共有・全体公開は不可）。連絡先は読み取り専用。

## 安全のしくみ
1. **承認の関門。** 書き込みの依頼が来ると、サーバーはまず「内容の要約」と**署名つきの許可証**だけを返します（ツール名と引数のハッシュにHMAC署名、有効2分、1回限り）。承認カードの**「承認して実行」だけ**が許可証を送り返します。引数の差し替え、使い回し、期限切れ、偽造、別ツールへの流用は拒否されます（`npm test` で確認。安全装置を壊すとテストが落ちることも確認済み）。
2. Enterでは承認されません（最初のフォーカスは「却下」）。Escで却下、2分放置でも却下。モデルがボタンを押すことはできません。
3. **プロンプトインジェクション対策。** メール本文・ファイルの中身・予定のメモは「信頼できない第三者のデータ」です。人格の指示で、その中の命令に従わず報告するようにしてあります。仮に従っても、書き込みの実行にはあなたのクリックが要ります。
4. **鍵の置き場所。** クライアントシークレットと更新トークン（refresh token）は、**ユーザー本人ごと**に、本人のデータ鍵で暗号化して保存します（クライアントIDは本人の設定、シークレットは本人の秘密、更新トークンは本人の `oauth_tokens` の行）。共通のGoogleクライアントはありません（決定 O2）。ブラウザには渡らず、画面にも表示しません。環境変数で渡す従来の方法は、自前で動かすスクリプト（`scripts/google-auth.mjs`）用で、プラットフォームでは使われません。ツールの結果は切り詰めて（メール6000字など）モデルに渡します。
5. 実行した書き込みは、サーバーの記録に `[audit]` として残ります（ツール名・危険度・短縮した引数・結果ID）。
6. いつでも解除：https://myaccount.google.com/permissions で E.L.V.A.R. を削除。

## 設定の流れ（最初に一度だけ・約15分・インストール不要）
詳細は **`/google-setup/`**（日本語）。概要：
1. Google Cloud でプロジェクトを作る。
2. 7つのAPI（Calendar・Gmail・Drive・Docs・Sheets・Tasks・People）を有効にする。
3. OAuth同意画面を作る（外部）。ブランディングを埋め（ホームページ・`/privacy/`・`/terms/` はアプリ内にあります。ロゴは入れない）、**「本番環境」に公開**（「テスト中」のままだとログインが7日で切れるはず。私の理解で、Googleの最新規則は未確認）。
4. **「ウェブ アプリケーション」**型のOAuthクライアントを作り、承認済みリダイレクトURIに、アプリの設定「Google」に表示される値（`https://（アプリのアドレス）/api/google/callback`）を登録する。
5. アプリの **設定 → Google** に、クライアントIDとシークレットを入れ、使うサービス（カレンダー・Gmail・ドライブ・ドキュメント・スプレッドシート・タスク・連絡先、読み取りのみ）を選ぶ。
6. **「Googleと連携」**を押す。Googleの画面が外部のブラウザ（Androidは Chrome のカスタムタブ、デスクトップはシステムのブラウザ）で開く。許可すると、アプリに戻ったとき自動で完了する。環境変数も、トークンの貼り付けも不要。
7. 設定 → Google の状態が「連携済み」になっていることを確認する。「切断」でGoogle側の許可も取り消せる。

仕組み：「Googleと連携」（`POST /api/elvar/connect/google/start`、ログイン中の本人のみ）が、PKCE（S256）と、32バイトの乱数の `state`（1回限り・10分）を付けたGoogleのURLを返す。サーバーは `sha256(state)` だけを保存し、途中の情報（クライアントIDとシークレット、PKCEの検証値、戻り先、スコープ）は `state` から導いた鍵で暗号化して、本人の行（`app.oauth_pending`）に置く。Googleから戻るブラウザ（`GET /api/google/callback`）にはログインの情報がないので、サーバーが `state` のハッシュから「誰の流れか」を調べ（定義者関数 `app.oauth_pending_owner`）、**その本人として**1回だけコードをトークンに交換（クライアントシークレットはブラウザに出ない）し、結果を同じ行に預ける。本人のアプリが `POST .../connect/google/claim` で受け取り（他のユーザーには見えない）、本人の鍵で暗号化して保存し、預けた情報は消す。戻り先のURIは、設定（`ELVAR_PUBLIC_ORIGIN`、Vercelではこのデプロイ自身のホスト）から決め、リクエストの Host からは決めない。連携が切れたとき（`invalid_grant`：取り消し・「テスト」の7日失効）は「再接続が必要です」と、通知欄・設定のバッジ・システムチェックで知らせる。

**別の方法（上級者）：** 「デスクトップ アプリ」型のクライアントと `google-auth.mjs`（Node.js 22以上、PKCE・ループバック）。`--readonly` で読み取り権限のみ要求。
