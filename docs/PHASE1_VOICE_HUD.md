# 音声会話・拍手ウェイク・HUD の仕組み

この文書は、声の会話と拍手ウェイクの技術メモです。もともとは最初の試作（オーナー1人用）の記録でしたが、共通のマルチユーザー基盤に合わせて書き直しました。
全体の設計は `docs/ELVAR_MULTIUSER.md`、HUD の部品は `docs/HUD_NOTES.md` にあります。

## 音声会話（Gemini Live）

```
ブラウザ（HUD・マイク・スピーカー） ──ws──►  Gemini Live   （直接。音声はサーバーを通らない）
        │  POST /api/live-token（ログイン中の本人として）
        ▼
サーバー: 本人の Gemini キー（暗号化して保存したもの）で、短命・1回限り・設定固定の一時トークンを発行する
          （人格・声・文字起こしの設定はサーバー側で固定。発行数は本人ごとに数える）
```

- キーは、**利用者本人の Gemini キー**です。プラットフォームの環境変数のキーには、フォールバックしません（`docs/ELVAR_MULTIUSER.md` の決定 M5）。
- 入力: マイク → AudioWorklet → 16 kHz モノラル PCM16 → Live へ送信。
- 出力: 24 kHz PCM16 → 再生 → HUD の球体が音量に反応します。話しかけて割り込むと、再生を止めます。
- 一時トークンには、`apiVersion: 'v1alpha'` を使います（SDK の型に合わせたもの）。
- モデル名は、環境変数 `GEMINI_LIVE_MODEL`（既定は `gemini-3.8-live`）です。モデル名は変わることがあるので、使う前に Google の最新の資料で確かめてください。控えのモデルは `GEMINI_LIVE_MODEL_FALLBACK` です。
- 聞き取りと反応の調整用の環境変数は `.env.example` にあります（`GEMINI_LIVE_SILENCE_MS`、`GEMINI_LIVE_PREFIX_MS`、`GEMINI_LIVE_END_SENSITIVITY`、`GEMINI_LIVE_START_SENSITIVITY`、`GEMINI_LIVE_INPUT_LANGS`）。
- 上限: Live の開始は、1時間に30回までが既定のハード上限です（運営者が変えられます）。Live の時間は、あなたの端末からの報告をもとに数えます。利用量の画面を見てください。
- Live の上限に達したときは、通常の音声モード（文章と音声の Gemini 呼び出し）が控えになります。
- 「考え中」の表示は、推定です（話し終えてから 700 ms 以上、答えが始まらないとき）。

## 拍手ウェイク（スタンバイ）

アプリを開いたまま背景にしているとき、拍手を2回すると、E.L.V.A.R. が起きます。Gemini Live につないで、時間帯に合ったあいさつを読み、そのあとマイクを開きます。Live につなげないときは、ブラウザの読み上げが控えになります。

- 検出は、ブラウザの AudioWorklet の中だけで行います。待ち受け中は、何も録音せず、保存せず、送りません。呼び出しの費用もかかりません。ブラウザのマイクの表示は、待ち受け中ずっと出ます。
- やめる: `?standby=0`（保存されます）。戻す: `?standby=1`。
- 状態の表示: `STANDBY`（待ち受け）、`CLAP ✓`（1回聞いた）、`TAP TO ARM`（ブラウザが音を止めているので、1回クリックが要る）、`MIC BLOCKED`、`WAKING`。
- 検出（`web/src/live/clap-detector.worklet.js`）: 高音を通すフィルター → 音量が雑音の床より十分大きく、急に立ち上がり、50 ms 以内に減衰する音。0.12〜0.75 秒の間隔の2回だけを拍手とします。残響と、3回目の音や拍手の連続は、はじきます。ブラウザのエコー除去・ノイズ抑制・自動音量は、待ち受けのマイクでは切ります（拍手の音が消えるため）。
- 感度: `?clapsens=2`（2 = 敏感）か、設定パネル。診断: `?clapdebug=1`。
- 2回目の拍手の瞬間に、画面を点灯して、Gemini への接続を並行して始めます。0.4 秒後に確認し、3回目の音や話し声なら取り消します。
- あいさつは固定の3文だけなので、音声を端末に一度だけ録音して保管します（IndexedDB。ユーザーごとの名前空間付き）。拍手のあと、すぐに再生できます。声や人格を変えると、古い録音は使われず、録り直します。`?pregreet=0` で、背景での録音をやめられます。
- 声の速さ: 既定は 1.2 倍。音程を変えずに、ブラウザで時間を縮めます（`?speed=1.5`、設定パネルでも変えられます）。
- Web ページには、できないことがあります。閉じたアプリを自分で起動すること、隠れた・最小化した窓を前面に出すことです。これは、下のデスクトップアプリと Chrome 拡張が担当します。iOS / Safari は、背景のマイクを止めます。

## 窓を前面に出す

- **デスクトップアプリ**（`desktop/`、Electron）: 隠れていても拍手を聞き続け、2回目の拍手で、窓を最前面に出します。トレイに常駐します。使い方は `desktop/README.md` にあります。
- **Chrome 拡張**（`extension/`）: ブラウザ利用者向けです。最小化した窓を戻して、タブを前面にします。アプリの `/extension/` ページに、ダウンロードと手順があります。
- Windows と macOS での挙動は、まだ確かめていません。

## 起動音楽と設定パネル

- 設定パネル（HUD の歯車、Ctrl+,、`?settings=1`）で、起動音楽（自分の MP3、80MB まで）、声の速さ、拍手から声までの間、拍手待ち受けの感度を設定できます。
- 起動音楽のファイルは、**この端末のブラウザの中**（IndexedDB。ユーザーごとの名前空間付き）にだけ保存されます。アップロードされません。
- 音楽は、2回目の拍手で1回だけ流れます（「ループする」も選べます）。声が出ている間は、音量を下げます。止めるには、画面下の `■ STOP`、Esc、デスクトップアプリのトレイのメニューを使います。

## 画面の配置

縦長の画面（幅 / 高さ < 1.05）では、スマホ用の HUD を使います。横長はデスクトップ用です。くわしくは `docs/HUD_NOTES.md` にあります。

## 確かめていないこと

- 本物の部屋・マイク・スピーカーでの拍手の検出（合成の音と、偽のマイクでの確認だけです）。
- 隠れた・最小化した窓での挙動（ヘッドレスのブラウザは、隠れた状態を報告しません）。
- Safari、Firefox、実機の iOS / Android。
- 1.2 倍以上の速さでの、実際の Gemini の声の聞こえ方。
