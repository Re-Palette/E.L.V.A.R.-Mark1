GOOGLE CONNECT

カレンダー・Gmail・ドライブ・ドキュメント・スプレッドシート・タスク・連絡先を、声で頼めるようにします。自分のGoogleアカウントに、自分のOAuthクライアントを作る方式です。初回だけ、約10分かかります。環境変数も、トークンの貼り付けも要りません。

アプリの設定を開く

0全体の流れ

  1. Google Cloud で、プロジェクトを作り、7つのAPIを有効にする。
  2. 同意画面を作り、自分をテストユーザーに入れ、公開ステータスを「本番」にする。
  3. OAuthクライアント（種類：ウェブ アプリケーション）を作り、下のリダイレクトURIを登録する。
  4. アプリの 設定 → Google に、クライアントIDとシークレットを入れて「Googleと連携」を押し、許可する。
登録するリダイレクトURI（手順3で、そのまま貼り付けます）
https://（このアプリのアドレス）/api/google/callback
アプリの設定の「Google」タブにも、同じ値が出ます（そちらが正確です）。

1プロジェクトを作る

  1. Google Cloud Console を、使うGoogleアカウントで開きます（初回は利用規約に同意します）。
  2. 画面上部のプロジェクト名（「プロジェクトを選択」）を押し、「新しいプロジェクト」を選びます。
  3. 名前を elvar にして「作成」。上に elvar と出ていること（選ばれていること）を確認します。

27つのAPIを有効にする

次のリンクを開き、それぞれ「有効にする」を押します。使わないサービスは、飛ばして構いません。

  • Google Calendar API
  • Gmail API
  • Google Drive API
  • Google Docs API
  • Google Sheets API
  • Google Tasks API
  • People API（連絡先）

3同意画面を作る

Google Auth Platform を開き、「開始」を押します（画面の見た目が古いときは、左メニュー「APIとサービス」→「OAuth 同意画面」。名前は少し違いますが、同じことをします）。

  1. アプリ情報：アプリ名に E.L.V.A.R.、サポートメールに自分のGmail。
  2. 対象：「外部」を選びます。
  3. 連絡先情報：自分のメールアドレス。
  4. 終了：ポリシーへの同意にチェックして、「続行」→「作成」。

4テストユーザーに自分を入れ、「本番」に切り替える

左メニューの「対象」（Audience）を開きます。

  1. テストユーザー：「ユーザーを追加」で、自分のGmailアドレスを入れて保存します。
  2. 公開ステータス：「アプリを公開」を押し、確認で「確認」。「本番環境」になれば完了です。
ここが大事です：「テスト」のままだと、7日で連携が切れます。
公開ステータスが「テスト」のアプリでは、Googleが更新用のトークンを7日で失効させます。1週間おきに「再接続が必要です」と出ます。
自分専用なら「本番」に切り替えてください。審査は要りません。同意画面に「Googleで確認されていないアプリ」と警告が出るだけで、自分で許可すれば使えます（他の人が使えるようになることもありません）。
  • 公開できずに「ブランディングを完成させてください」と出たら、左メニューの「ブランディング」で、次を入れて保存します（ロゴは入れません）。
    欄入れる値
    アプリのホームページhttps://（このアプリのアドレス）/
    プライバシー ポリシーhttps://（このアプリのアドレス）/privacy/
    利用規約https://（このアプリのアドレス）/terms/
    承認済みドメインアドレスの https:// と / を除いた部分（例：〇〇.vercel.app）
  • 左メニューの「データアクセス」は、何もしなくて構いません（権限は、連携のときの許可画面で求められます）。

5OAuthクライアントを作る

  1. 左メニューの「クライアント」（古い画面では「認証情報」→「＋認証情報を作成」→「OAuth クライアント ID」）を開き、「クライアントを作成」を押します。
  2. アプリケーションの種類：「ウェブ アプリケーション」を選びます。「デスクトップ アプリ」や「Android」ではありません。
  3. 名前は elvar など、なんでも構いません。
  4. 「承認済みのリダイレクト URI」の「URIを追加」を押し、上のリダイレクトURIを一字一句そのまま貼り付けます。
    「承認済みの JavaScript 生成元」は空のままです。最後に / を足す、http と https を間違える、などでも失敗します。
  5. 「作成」を押すと、クライアントIDとクライアントシークレットが表示されます。シークレットは、この画面で必ずコピーしてください（あとで見られないことがあります）。

6アプリで連携する

  1. E.L.V.A.R. の設定 → Google（ここから開けます）を開きます。
  2. クライアントIDとクライアントシークレットを貼り付けます。使うサービスにチェックを入れます（読み取りだけにもできます）。
  3. 「Googleと連携」を押します。Googleの画面が、外部のブラウザ（スマホではChromeのタブ）で開きます。
  4. 使うアカウントを選びます。「Googleで確認されていないアプリ」と出たら、「詳細」→「E.L.V.A.R.（安全ではないページ）に移動」を選びます（自分で作ったアプリなので問題ありません）。
  5. 権限の一覧で、すべてにチェックが入っていることを確認して「続行」。「連携しました」と出たら、アプリに戻ります。自動で完了します。

つながったら、話しかけてみます：「今日の予定を教えて」「未読のメールを3件、要点だけ」「明日の15時に打ち合わせを入れて」（書き込みは、画面の承認カードで確認します）。

7うまくいかないとき

  • redirect_uri_mismatch：手順5で登録したURIが、1文字でも違います。アプリの設定「Google」に出ているURIを、もう一度正確に登録します。
  • アクセスをブロック／このアプリは審査プロセスを完了していません：自分のGmailが「テストユーザー」に入っていません（手順4）。
  • invalid_client / 「トークンの発行を断りました」：クライアントIDかシークレットが違う、またはクライアントの種類が「ウェブ アプリケーション」ではありません（手順5）。
  • 「更新用のトークンが返りませんでした」：Googleアカウントの権限の管理で E.L.V.A.R. を一度削除してから、もう一度「Googleと連携」を押します。
  • 「再接続が必要です」と出た：連携が切れています（取り消した／「テスト」のまま7日たった／パスワードを変えた）。設定の「Google」で「再接続」を押します。繰り返すなら、手順4の「本番」を確認します。
  • サービスが使えない（「許可されていません」）：設定の「Google」でサービスにチェックを入れて、もう一度「再接続」を押します。許可の画面で一部のチェックを外していないかも確認します。
  • Google の画面が、アプリの中で開いてしまう：「disallowed_useragent」と出ます。アプリの設定から押し直してください（外部のブラウザで開く作りです）。

8できること・安全のしくみ

サービスすぐ実行（読むだけ）画面で「承認」したときだけ実行
カレンダー予定の確認、空き時間予定の追加・変更・削除
Gmail検索、本文を読む下書き作成、送信、ゴミ箱へ移動
ドライブ・ドキュメント・スプレッドシート検索、中身を読む文書の作成・追記、セルの更新・追加、ゴミ箱へ移動、特定の1人への共有
タスク一覧追加・完了・削除
連絡先検索（読み取りのみ）
  • 書き込みは、画面の承認カードで「承認して実行」を押したときだけ実行されます。Enterキーでは承認されません。Escか2分放置で、自動的に却下されます。
  • 削除はゴミ箱に移すだけです。メール本文に「これを送れ」と書かれていても従いません。
  • クライアントシークレットと更新トークンは、サーバーで暗号化して保存します。ブラウザには渡らず、画面にも表示されません。
  • いつでも解除できます：設定の「Google」の「切断」（Google側の許可も取り消します）、またはGoogleアカウントの権限の管理。
自分のサーバーで環境変数を使う方へ

アプリの設定を使わず、環境変数だけで動かすこともできます（読み取り専用の「環境変数モード」）。GOOGLE_CLIENT_ID・GOOGLE_CLIENT_SECRET・GOOGLE_REFRESH_TOKEN を設定します。リフレッシュトークンは、google-auth.mjs（Node.js 22以上、「デスクトップ アプリ」型のクライアント）で取れます。この場合、サービスの絞り込みはできず、すべての道具が使えます。
