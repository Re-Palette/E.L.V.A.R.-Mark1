E.L.V.A.R. Google連携の設定

カレンダー・Gmail・Drive（ドキュメント／スプレッドシート）・タスク・連絡先を、声で扱えるようにします。最初に一度だけ、約15分の設定が必要です。

  • 書き込みは、画面に出る承認カードで「承認して実行」を押したときだけ実行されます。Enterキーでは承認されません。Escか、2分放置で、自動的に却下されます。
  • 削除はゴミ箱に移すだけ（約30日は戻せます）。完全な削除はしません。共有は、指定した1人のGoogleアカウントだけで、「リンクを知っている全員」は使いません。
  • メール本文などに「これを送れ」と書かれていても従いません（あなたに報告します）。仮に従っても、実行には必ずあなたの承認が要ります。
  • 鍵（クライアントシークレットなど）は、サーバーの環境変数にだけ置きます。ブラウザには渡りません。

0準備：何もインストールしません

パソコンに、新しいソフトを入れる必要はありません。ブラウザだけで、最後まで進められます。
（コマンドの操作が平気な方向けに、Node.js を使う別の方法を、いちばん下に残してあります。）

1Google Cloud でプロジェクトを作る

  1. Google Cloud Console を、E.L.V.A.R. で使うGoogleアカウントで開きます（初回は利用規約への同意を求められます）。
  2. 画面の上のほうにあるプロジェクト名の部分（「プロジェクトを選択」）を押し、「新しいプロジェクト」を選びます。
  3. プロジェクト名に elvar と入力して「作成」。作成後、そのプロジェクトが選ばれている（上に elvar と出ている）ことを確認します。

27つのAPIを有効にする

次のリンクを順に開き、それぞれ「有効にする」（Enable）を押します。（リンクが開かないときは、左メニュー「APIとサービス」→「ライブラリ」で、名前を検索してください。）

  1. Google Calendar API
  2. Gmail API
  3. Google Drive API
  4. Google Docs API
  5. Google Sheets API
  6. Google Tasks API
  7. People API（連絡先用）

3「同意画面」を作る（細かい手順）

「このアプリが、あなたのGoogleのどこにアクセスするか」をGoogleに登録する画面です。入力するのは、アプリ名とメールアドレスだけで、あとは基本的に飛ばして構いません。

まず、どちらの画面か確認します。手順2までを終えたあと、アドレスバーに次のどちらかを入力して開いてください。
  • console.cloud.google.com/auth/overview を開いて、「Google Auth Platform」と書かれた画面が出る → 下の「A. 新しい画面」へ。
  • 上が開けない・古い見た目の画面になる場合は、console.cloud.google.com/apis/credentials/consent を開く → 下の「B. 古い画面」へ。
どちらの場合も、画面の上に「elvar」（手順1で作ったプロジェクト）が選ばれていることを、先に確認してください。

A. 新しい画面（Google Auth Platform）の場合

「Google Auth Platform はまだ構成されていません」と出て、「開始」ボタンがあるはずです。それを押すと、4つの段階に分かれた入力が始まります。

  1. 段階1「アプリ情報」
    • アプリ名：E.L.V.A.R. と入力します。
    • ユーザー サポートのメール：右の▼を押して、ご自身のGmailアドレスを選びます（1つしか出ません）。
    • 右下の「次へ」を押します。
  2. 段階2「対象」
    • 「外部」を選びます（「内部」は選べないか、会社のGoogle Workspace用です）。
    • 「次へ」を押します。
  3. 段階3「連絡先情報」
    • メールアドレス：ご自身のメールアドレスを入力します（Googleからの通知が届く先です）。
    • 「次へ」を押します。
  4. 段階4「終了」
    • 「Google API サービス：ユーザーデータに関するポリシーに同意します」のチェックボックスにチェックを入れます。
    • 「続行」を押し、続けて「作成」を押します。
  5. 「概要」の画面に変わります。これで同意画面の本体は完成です。次に、左のメニューで「対象」（英語表示では Audience）を押します。
  6. 「対象」の画面で2つのことをします。
    • ① テストユーザーを追加する：画面の下のほうの「テストユーザー」の「+ Add users」（ユーザーを追加）を押し、ご自身のGmailアドレスを入力して「保存」します。
    • ② アプリを公開する：画面の上のほうに「公開ステータス：テスト」と書かれ、その下に「アプリを公開」（Publish app）ボタンがあります。それを押し、確認の画面で「確認」を押します。表示が「本番環境」（In production）に変われば成功です。
      ※ 「テスト」のままだと、ログインが7日で切れるはずです。公開しても、あなた専用のアプリなので、他の人が使えるようになることはありません。確認の画面に「確認が必要」のような注意が出ても、そのまま進めて構いません。
  7. 「ブランディングを完成させてください」と出て、公開できないとき
    左メニューの「ブランディング」（Branding）を開き、次のように入力して「保存」します。アプリのロゴは、入れないでください（入れると、Googleの審査が必要になることがあります）。
    欄入れる値
    アプリ名（*）E.L.V.A.R.
    ユーザー サポートメール（*）ご自身のGmail
    アプリケーションのホームページhttps://（このアプリのアドレス）/
    アプリケーション プライバシー ポリシー リンクhttps://（このアプリのアドレス）/privacy/
    アプリケーション利用規約 リンクhttps://（このアプリのアドレス）/terms/
    承認済みドメイン下の注意を見てください
    デベロッパーの連絡先情報 メールアドレス（*）ご自身のメールアドレス
    ※ （*）は必須です。ホームページ・ポリシー・規約は、このページを開いているアドレスのもの（自動で入ります）を使います。先に、それらのページが開けることを、ブラウザで確認してください。
    • 承認済みドメイン：「ドメインの追加」を押し、アドレスのhttps://と/を除いた部分（例：〇〇.vercel.app）を入れます。「ドメインが無効」のように拒否されたら、空のままにして保存を試してください（このアプリは、ログインにドメインを使わないので、必須でないはずです）。それでも進めないときは、表示された文言を教えてください。
  8. 左のメニューの「データアクセス」（Data Access）は、今は何もしなくて構いません（権限は、手順5のログインのときに、許可の画面で求めます）。
    もし手順5で「アクセスをブロック：このアプリのリクエストは無効です」のようなエラーが出たときだけ、ここで「スコープを追加または削除」を押して、権限（Calendar、Gmail、Drive、Docs、Sheets、Tasks、Contacts）を追加してください。

B. 古い画面（OAuth 同意画面）の場合

  1. User Type（ユーザーの種類）の画面：「外部」（External）を選び、「作成」を押します。
  2. 「アプリ情報」の画面
    • アプリ名：E.L.V.A.R.
    • ユーザー サポートメール：ご自身のGmailを選びます。
    • 「アプリのロゴ」「アプリのドメイン」は空のままで構いません。
    • 一番下の「デベロッパーの連絡先情報」のメールアドレスに、ご自身のメールアドレスを入力します。
    • 「保存して次へ」を押します。
  3. 「スコープ」の画面：何も追加せず、そのまま「保存して次へ」を押します。
  4. 「テストユーザー」の画面：「+ ADD USERS」（ユーザーを追加）を押し、ご自身のGmailアドレスを入力して「追加」。続けて「保存して次へ」を押します。
  5. 「概要」の画面：内容を確認して、一番下の「ダッシュボードに戻る」を押します。
  6. ダッシュボードの「公開ステータス」が「テスト」（Testing）になっています。その下の「アプリを公開」（PUBLISH APP）ボタンを押し、確認の画面で「確認」を押します。表示が「本番環境」（In production）に変われば成功です。
    ※ 「テスト」のままだと、ログインが7日で切れるはずです。公開しても、あなた専用のアプリなので、他の人が使えるようになることはありません。
これでできたかの確認：「公開ステータス」が「本番環境」になっていて、テストユーザーにご自身のGmailが入っていればOKです。
うまく進まなくなったら、いま見えている画面の上のほうに書かれている文字と、押したいボタンの名前を教えてください。そこから探します。

4ログイン用の「クライアントID」を作る（ウェブ アプリケーション型）

  1. 左メニューの「認証情報」を開き、上の「＋ 認証情報を作成」→「OAuth クライアント ID」を選びます。
  2. アプリケーションの種類：「ウェブ アプリケーション」を選びます（「デスクトップ アプリ」ではありません。前に作ったものがあっても、別に、もう1つ作ります）。名前は elvar-web など。
  3. 下のほうの「承認済みのリダイレクト URI」の「＋ URI を追加」を押し、次のアドレスを一字一句そのまま貼り付けます。
    https://（このアプリのアドレス）/api/google/callback
    ※ 「承認済みの JavaScript 生成元」は、空のままで構いません。アドレスの最後に / を足したり、http と https を間違えたりすると、ログインできません。
  4. 「作成」を押します。クライアント IDとクライアント シークレットが表示されるので、メモ帳に控えます。
    シークレットは、他の人に見せたり、チャットに貼ったりしないでください（私にも貼らないでください）。

5Vercel に2つ登録して、再デプロイする

  1. Vercel で、このアプリのプロジェクトを開き、「Settings」→「Environment Variables」を開きます。
  2. 次の2つを、名前と値のペアで追加します（Environment は「Production」を含めて選択）。
    名前（Key）値（Value）
    GOOGLE_CLIENT_ID手順4の「クライアント ID」
    GOOGLE_CLIENT_SECRET手順4の「クライアント シークレット」
  3. すでに ELVAR_ACCESS_TOKEN が登録されていることも確認してください（Google連携の入口を守るために必要です）。
  4. 「Deployments」を開き、最新のデプロイの右の「…」から「Redeploy」を押します（完了まで1〜2分）。

6ボタンを押して、Googleにログインする

  1. 再デプロイが終わったら、このページを開き直して、下のボタンを押します。
  2. Googleのページが開きます。使うGoogleアカウントを選びます。
  3. 「Google でまだ確認されていないアプリ」と出たら、「詳細」→「E.L.V.A.R.（安全ではないページ）に移動」を選びます（ご自身で作ったアプリなので問題ありません）。
  4. 権限の一覧が出ます。すべての項目にチェックが入っていることを確認して、「続行」を押します。
  5. 「Googleにログインできました ✓」というページが開き、長い文字列が表示されます。「コピー」を押します。
    この値は、あなたのGoogleに入るための鍵です。この画面は、一度閉じると二度と表示できません。他の人には見せないでください（私にも貼らないでください）。
  6. Vercel の「Environment Variables」に戻り、次を追加して、もう一度「Redeploy」します。
    名前（Key）値（Value）
    GOOGLE_REFRESH_TOKENいまコピーした長い文字列

7つながったか確認する

  1. このページの上の「状態」が「接続済み ✓」になることを確認します（「状態を再確認」ボタンで更新）。アプリの歯車（設定）→「Google連携」→「接続を確認」でも同じです。
  2. E.L.V.A.R. に話しかけてみます：
    ・「今日の予定を教えて」　・「未読のメールを3件、要点だけ教えて」　・「明日の15時に打ち合わせを入れて」→ 画面に承認カードが出ます。
うまくいかないとき
  • 「ログイン切れ」：手順6のボタンをもう一度押して、GOOGLE_REFRESH_TOKEN を新しい値に入れ替え、再デプロイします。
  • 「未設定」：手順5・6の3つの値の名前の綴りと、再デプロイを確認します。
  • ボタンを押したあとに Google の画面で「redirect_uri_mismatch」と出たら、手順4で登録したアドレスが、一字でも違います。https://…/api/google/callback を、もう一度正確に登録し直してください。
  • 「アクセストークンが違います」：ELVAR_ACCESS_TOKEN が、アプリに保存した値と一致しているか確認します。
  • 「更新トークンが返りませんでした」と出たら、Googleアカウントの権限の管理で E.L.V.A.R. を一度削除してから、手順6をやり直します。
  • 画面の名前が違って迷ったら、見えている画面の名前を教えてください。一緒に探します。
別の方法：Node.js を使う（コマンド操作が平気な方向け）

手順4で「デスクトップ アプリ」型のクライアントを作り、PowerShell で次を実行する方法です（Node.js 22以上が必要）。

  1. google-auth.mjs を C:\elvar に保存します。
  2. PowerShell で、cd C:\elvar → $env:GOOGLE_CLIENT_ID="…" → $env:GOOGLE_CLIENT_SECRET="…" → node google-auth.mjs を順に実行し、ブラウザで許可すると、GOOGLE_REFRESH_TOKEN=… が表示されます。
  3. 3つの値（ID・シークレット・トークン）を Vercel に登録して、再デプロイします。

いつでも解除できます：Googleアカウントの権限の管理で、E.L.V.A.R. を削除してください。
